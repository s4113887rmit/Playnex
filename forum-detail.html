Hey everyone,

I'm currently managing a custom server primarily for Southeast Asian players. We are using Radmin VPN to configure the LAN play network, which usually runs smoothly. However, recently we've been experiencing massive TPS (Ticks Per Second) drops whenever a player activates a specific custom datapack ability.

I've written some complex scoreboard logic to manage the ability cooldowns. It looks something like this:

execute as @a[scores={ability_cooldown=1..}] run scoreboard players remove @s ability_cooldown 1
execute as @a[scores={ability_active=1}] at @s run function custom:skills/fire_blast

Could the continuous execution of this logic be causing the performance bottleneck for the SEA player base? Any advice on performance optimization or restructuring this logic would be highly appreciated.

Joined: Jan 2026

The issue is definitely tied to how your server handles the recursive function calls. Checking that scoreboard logic every single tick for every connected player over a VPN will absolutely drain your TPS.

Instead of checking every tick, try implementing a macro or scheduling the function to only check when a specific event is triggered rather than looping it infinitely. Also, ensure your Radmin VPN routing isn't creating packet loss, which can simulate server lag.
